F-Med Onco LLM

肿瘤临床疗效预测垂直模型 —— 面向临床开发、BD 与立项、转化医学、投资尽调

F-Med Onco LLM 建立在 F-Med 架构之上——把 DeepSeek 已验证的 MLA、细粒度 + 共享专家 MoE、MTP、GRPO，按临床数据的性质重新排布的垂直模型。

定位

护城河不在模型权重，在一个持续更新、字段级可溯源的临床疗效事实库。

通用医疗大模型回答「这个靶点在二线非小细胞肺癌里大概能做到多少 ORR」时，数字来自参数记忆—— 张冠李戴、无法回溯、无法被证伪。本项目反过来做：先把疗效事实结构化，再谈模型。 每一个 ORR、mPFS、HR 都带 NCT 号与 DOI，可以被审稿式核查。

F-Med 架构特点

不是从零造轮子，而是把 DeepSeek 已验证的组件按临床数据的性质重新排布。

四个组件各自对应临床数据的一项具体性质；左为组件，右为「为什么临床数据需要它」
组件做了什么临床数据为什么需要它
MLA
潜向量注意力		把 KV cache 压成低秩潜向量，长上下文的显存瓶颈被解开临床试验方案书、CSR、整册年会摘要都极长——要能一次读完，而不是分段喂
MoE
细粒度 + 共享专家		细粒度专家按瘤种、终点类型、法规辖区切分；共享专家承载跨瘤种通用的临床统计与话术临床语域天然分区，但基础临床统计是所有分区共用的，不该让每个专家重学一遍
MTP
多 token 预测		多 token 训练目标，并提升结构化抽取吞吐疗效字段强耦合且成对出现：ORR 的分子分母、HR 与其置信区间，逐 token 预测容易拆散
GRPO
组相对策略优化		按试验分组算组内相对优势，无需人工偏好标注即可做强化学习疗效预测的奖励客观可验证（ORR 误差、HR 方向对错），且「同一试验多个臂」天然成组

架构：四层分离

能力进权重，出处进检索，疗效数字进事实库，外部数据库进工具调用。

参数层CPT + SFT 机制—疗效先验 · 终点选择 · 试验设计推理
检索层RAG 带出处引用 期刊全文 · 年会摘要 · 答案可回链 DOI
事实库层结构化疗效事实表 ORR / DCR / mPFS / mOS / HR 与置信区间 · 线数 · 标志物亚组
工具层函数调用 ClinicalTrials.gov · PubMed/PMC · ChEMBL · openFDA

抽取即校验：HR 与置信区间互洽、ORR 分子分母闭合、时间单位归一化、 与注册库同 NCT 记录交叉比对。校验不通过的记录打标保留而非丢弃，用于量化抽取精度。

约 44% 的已完成 II/III 期试验带有可直接解析的结构化结果，量级在万条试验级记录， 足以支撑试验级疗效预估。剩余约 56% 需靠期刊文献与年会摘要抽取补齐—— 这正是抽取管线的价值，也是整个系统的真正上限所在： 决定性能天花板的是召回率，不是模型容量。

私有数据层

公开层之外叠加四类私有数据。其中卫健委私有数据库与申办方未公开数据是本项目相对纯公开语料模型的 关键增量——阳性结果更易发表，只用公开文献会系统性高估疗效。

  • 卫健委私有数据库——用于模型训练的国家级临床数据资产
  • 院内真实世界队列——疗效随访、影像评估、分子分型
  • 申办方未公开试验数据——含阴性结果，用于纠正发表偏倚
  • 专家标注集——抽取校验金标准与疗效可信度分级
数据合规前置。卫健委私有数据库与院内队列的使用，以数据使用协议、伦理审批与去标识化 处理为前提；相关授权文件在尽调时单独提供，不在本页列示。

怎么证明「最准确」

这是目标，不是现状。证明方式先于结论公开。

  1. 时间切分，不是随机切分。早期试验训练、近期试验测试，杜绝信息泄漏—— 随机切分会让同一试验的不同报告同时落入训练与测试集，把记忆伪装成预测。
  2. 两个硬指标。ORR 回归考 MAE 与预测区间覆盖率；PFS 获益方向考 AUC 与校准曲线。 不做主观打分，不做人工偏好评测。
  3. 三条对照基线。通用 LLM 零样本、表格模型（梯度提升）、两者融合，同一测试集横向比。

能力边界

写在正面而不是脚注里，因为这是数据决定的，不是调参能解决的：

  • 公开数据仅汇总级，个体患者疗效预测不在能力范围内。
  • 发表偏倚会系统性高估疗效，须在建模中显式处理，私有阴性结果是主要抓手。
  • 年会摘要与付费墙文献的召回率是整体性能上限，而非模型容量。
  • 截至目前模型权重尚未训练，当前交付为事实库与评测基准。
